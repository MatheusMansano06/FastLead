## 🎯 DOIS MODELOS EM COMPETIÇÃO

### Modelo A: TABLET + CPM (Custo Por Mil impressões)
- **Foco**: Branding, alcance puro
- **Monetização**: Anunciante paga por impressão (CPM)
- **Tipo de anunciante**: Marcas consolidadas (bebida, telecom, etc)
- **Controle**: FastLead controla tela, anúncios em rotação
- **Risco**: Receita depende de ocupação de espaço publicitário

### Modelo B: QR CODE + AFILIADO (CPA/CPL)
- **Foco**: Performance, conversão, dados
- **Monetização**: Anunciante paga por lead/venda (CPA/CPL)
- **Tipo de anunciante**: PMEs, performance, promoções
- **Controle**: Motorista é afiliado, incentivado a vender
- **Risco**: Receita depende de scan → lead → conversão

## 🎬 MECÂNICA DE MONETIZAÇÃO

### Modelo A: TABLET (CPM)

**Fluxo**:
```
Anunciante paga CPM
    ↓
Campanha entra na rotação do tablet
    ↓
Passageiro vê anúncio (impressão = 1/1000 de receita)
    ↓
FastLead recebe R$ por 1.000 impressões
    ↓
Custos (taxa motorista 35%, impostos 12%, etc)
    ↓
Lucro FastLead
```

**Premissas**:
- **CPM**: R$ 25 por 1.000 impressões
- **Spots vistos**: 28 por passageiro/mês
- **Pasageiros**: 507/veículo/mês
- **= Impressões**: 507 × 28 = 14.196/veículo/mês
- **Taxa ocupação (fill)**: 25-60% (depende da demanda de anunciantes)

**Cálculo de Receita/Veículo**:
```
14.196 impressões × R$ 25 CPM ÷ 1.000 × 60% ocupação
= 14.196 × 0,025 × 0,60
= R$ 212,94 bruto/mês (maduro)
```

**Distribuição (% da receita bruta)**:
- Motor.ista revenue share: 35% = R$ 74,53
- Impostos: 12% = R$ 25,55
- Produção conteúdo: 5% = R$ 10,65
- Comissão parceiros: 7% = R$ 14,91
- Processamento pgto: 2,5% = R$ 5,32
- **FastLead Margin**: ~38,5%

---

### Modelo B: QR CODE (CPA/CPL)

**Fluxo**:
```
Anunciante paga por LEAD ou VENDA (R$ 40/conversão)
    ↓
QR exibido no tablet (8 QRs diferentes em rotação)
    ↓
Passageiro scanneia (taxa: 0,6-1,0% por QR dependendo fase)
    ↓
Clica no link → landing page FastLead/marca
    ↓
Deixa contato ou completa compra (taxa conversão: 15%)
    ↓
FastLead recebe R$ 40 por lead
    ↓
Custos (comissão motorista 30%, impostos 12%, etc)
    ↓
Lucro FastLead
```

**Premissas**:
- **8 QRs** diferentes em rotação por veículo
- **Taxa scan/QR**: 0,6% (Fase 1) → 1,0% (Fase 3)
- **Scan efetivo/passageiro**: 8 × 0,01 = 8%
- **Taxa conversão**: 15% (scan → lead)
- **Receita/conversão**: R$ 40
- **Passageiros**: 507/veículo/mês

**Cálculo de Receita/Veículo**:
```
507 passageiros × 8% scan rate × 15% conversão × R$ 40
= 507 × 0,08 × 0,15 × 40
= R$ 243,36 bruto/mês (maduro)
```

**Distribuição (% da receita bruta)**:
- Comissão motorista/afiliado: 30% = R$ 73,01
- Impostos: 12% = R$ 29,20
- Produção landing/IA: 2% = R$ 4,87
- Comissão parceiros rede: 5% = R$ 12,17
- Plataforma afiliados/pgto: 3% = R$ 7,30
- **FastLead Margin**: ~48%

## 🔑 ANÁLISE DE RISCO

### Modelo A (Tablet/CPM) — Risco BAIXO
✅ **Receita previsível**
- CPM é garantido: anunciante paga independente de clique
- Risco é ocupação de espaço (fill rate)

⚠️ **Desafios**:
- Precisa de muitos anunciantes grandes para preencher grade
- Prova de ROI difícil (branding é longo prazo)
- Sazonalidade: orçamentos anuais

❌ **Difícil de escalar**:
- Tablet é ativo (requer suporte, updates)
- Barreira para motorista: R$ 500 + tempo setup
- Churn do lado do anunciante impacta

---

### Modelo B (QR/Afiliado) — Risco MÉDIO-ALTO
⚠️ **Receita depende de funil**
- Precisa: anunciante → brand → scan → conversão
- Qualquer passo quebrado = sem receita

✅ **Potencial de crescimento**:
- Muito mais escalável (PMEs gostam de pay-per-performance)
- Fácil onboarding (QR é simples)
- Motorista é evangelista (ganha comissão)

❌ **Desafios**:
- Taxa conversão é crítica (15% é otimista?)
- Spam/fraud risk (clicks falsos)
- Dependência de landing pages boas

### 1️⃣ MODELO DE PAGAMENTO (Entidade Principal)

```typescript
// Banco de Dados - Models principais

enum PaymentModel {
  CPM = "CPM"              // Tablet: por impressão
  CPA = "CPA"              // QR: por ação (lead)
  CPL = "CPL"              // QR: por lead qualificado
  HYBRID = "HYBRID"        // Ambos na mesma campanha
}

enum PaymentStatus {
  PENDING = "PENDING"      // Aguardando processamento
  VERIFIED = "VERIFIED"    // Dados validados, pronto pagar
  PROCESSED = "PROCESSED"  // Pagamento realizado
  REJECTED = "REJECTED"    // Fraud/erro
}

model CampaignPaymentConfig {
  id                String   @id @default(cuid())
  company_id        String
  campaign_id       String   @unique
  
  // Tipo de pagamento
  model             PaymentModel @default(HYBRID)
  
  // Tablet CPM
  cpm_value         Decimal? @db.Decimal(10, 2)  // R$ por 1.000
  cpm_enabled       Boolean  @default(true)
  
  // QR Afiliado
  cpa_value         Decimal? @db.Decimal(10, 2)  // R$ por conversão
  cpl_value         Decimal? @db.Decimal(10, 2)  // R$ por lead qualificado
  conversion_target Int?     @default(15)         // 15% conversão target
  
  // Comissão do motorista
  motorista_share   Decimal  @db.Decimal(5, 2)   // % (30-35%)
  
  // Limites & caps
  daily_budget      Decimal? @db.Decimal(12, 2)
  total_budget      Decimal  @db.Decimal(12, 2)
  budget_spent      Decimal  @default(0)
  
  // Timestamps
  created_at        DateTime @default(now())
  updated_at        DateTime @updatedAt
  
  // Relations
  company           Company  @relation(fields: [company_id], references: [id])
  campaign          Campaign @relation(fields: [campaign_id], references: [id])
  transactions      PaymentTransaction[]
}

model PaymentTransaction {
  id                        String    @id @default(cuid())
  company_id                String
  campaign_id               String
  motorista_id              String
  config_id                 String
  
  // Tipo de evento
  transaction_type          String    // "IMPRESSION" | "SCAN" | "CONVERSION" | "LEAD"
  
  // Dados do evento
  event_id                  String?   // Link para ScanEvent ou ImpressionEvent
  quantity                  Int       @default(1)      // qtd impressões ou leads
  unit_price                Decimal   @db.Decimal(10, 2)
  gross_amount              Decimal   @db.Decimal(12, 2)
  
  // Descontos & taxas
  motorista_share           Decimal   @db.Decimal(12, 2)  // O que motorista recebe
  fastlead_net              Decimal   @db.Decimal(12, 2)  // O que FastLead fica
  taxes_amount              Decimal   @db.Decimal(12, 2)  // Impostos (12%)
  platform_fee              Decimal   @db.Decimal(12, 2)  // Taxa operacional
  
  // Status
  status                    PaymentStatus @default(PENDING)
  fraud_score               Float?    // 0-100, risco de fraude
  
  // Período de cobrança
  billing_period_start      DateTime
  billing_period_end        DateTime
  processed_at              DateTime?
  
  // Timestamps
  created_at                DateTime  @default(now())
  updated_at                DateTime  @updatedAt
  
  // Relations
  company                   Company   @relation(fields: [company_id], references: [id])
  campaign                  Campaign  @relation(fields: [campaign_id], references: [id])
  motorista                 MotoristProfile @relation(fields: [motorista_id], references: [id])
  config                    CampaignPaymentConfig @relation(fields: [config_id], references: [id])
  
  @@index([campaign_id])
  @@index([motorista_id])
  @@index([status])
  @@index([billing_period_start])
}

model PaymentBatch {
  id                String    @id @default(cuid())
  company_id        String
  
  // Período de cobrança
  period_start      DateTime
  period_end        DateTime
  
  // Dados agregados
  total_transactions  Int
  total_gross_amount  Decimal   @db.Decimal(12, 2)
  total_motorista_share Decimal @db.Decimal(12, 2)
  total_fastlead_net  Decimal   @db.Decimal(12, 2)
  
  // Status
  status            String    @default("DRAFT")  // DRAFT | READY | PROCESSING | PAID
  processed_at      DateTime?
  paid_at           DateTime?
  
  created_at        DateTime  @default(now())
  
  company           Company   @relation(fields: [company_id], references: [id])
  
  @@index([status])
  @@index([period_start])
}
```

### 5️⃣ CALCULAR RECEITA REAL

**Função auxiliar**:

```typescript
function calculatePayment(
  transaction: {
    quantity: number;        // impressões ou leads
    unit_price: number;      // R$ por impressão/lead
    motorista_share: number; // % (0.30)
    tax_rate: number;        // 0.12
  }
): {
  gross_amount: number;
  motorista_share: number;
  taxes: number;
  fastlead_net: number;
} {
  const gross = transaction.quantity * transaction.unit_price;
  
  const motorista = gross * transaction.motorista_share;
  const taxes = gross * transaction.tax_rate;
  
  // Custos operacionais (simplificado)
  const content_prod = gross * 0.05;      // Produção conteúdo
  const partner_comm = gross * 0.07;      // Comissão parceiros
  const processing = gross * 0.025;       // Processamento pgto
  
  const total_costs = motorista + taxes + content_prod + partner_comm + processing;
  const fastlead_net = gross - total_costs;
  
  return {
    gross_amount: gross,
    motorista_share: motorista,
    taxes: taxes,
    fastlead_net: fastlead_net
  };
}
```

## ⚠️ DESAFIOS DE IMPLEMENTAÇÃO

### 1. Detecção de Fraude (QR)
**Problema**: Clicks falsos, bot scans, etc.

**Solução**:
- Hash de (IP + User-Agent + dia) para deduplicação
- Geolocalização consistente
- Validação de landing page performance
- Fraud score por motorista/campaign

### 2. Validação de Conversão
**Problema**: Como provar que um scan levou a uma venda?

**Solução**:
- Link UTM único por motorista/campanha
- Webhook da marca confirmando conversão
- Landing page FastLead captando leads
- Pixel de retargetamento

### 3. Evitar Gaming
**Problema**: Motorista incentivado a gerar scans falsos

**Solução**:
- Monitor de taxa de conversão por motorista
- Suspension automática se < 5% conversão
- Validação geográfica
- Manual review de outliers

### 4. Processamento de Pagamento
**Problema**: Stripe cobra 2,9% + R$ 0,30. Muitos motoristas = muita taxa.

**Solução**:
- Pagar 1x/mês em lote (não por transação)
- Usar Pix no Brasil (gratuito entre contas)
- Account segregation (empresa de pagamentos)
